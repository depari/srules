# 리팩토링 하네스 (Refactoring Harness)

## Phase 1: 목표 설정
- [ ] **대상 선정**: 코드 복잡도, 중복성, 의존성 결합도가 높은 모듈 식별
- [ ] **목표 정의**: 리팩토링을 통해 얻고자 하는 성능 향상, 가독성 개선, 결합도 완화 등의 목표 설정
- [ ] **안전망 확보**: 리팩토링 시작 전 전체 테스트(`npm test`)가 통과 상태인지 확인

## Phase 2: 점진적 개선
- [ ] **동작 유지**: 외부 인터페이스의 변경 없이 내부 구현만 점진적으로 변경
- [ ] **Small Steps**: 작업을 작은 단위로 쪼개어 수시로 테스트 확인
- [ ] **중간 테스트**: 각 단계마다 관련 단위 테스트 실행으로 기능 파손 방지

## Phase 3: 최종 검증
- [ ] **전체 테스트 통과**: 리팩토링 후에도 모든 테스트 케이스가 100% 통과함을 확인
- [ ] **기술 부채 해소 확인**: 당초 목표했던 설계 개선 가시성 확보

## Phase 4: 마감
- [ ] **구문 오류 및 빌드 확인**: 리팩토링 과정에서 구문 오류나 `npm run lint`, `npm test`, `npx playwright test`, `npm run build` 에러가 발생하지 않았는지 최종 확인 (필수)
- [ ] **의존성 정합성 확인**: `package.json` 변경 시 로컬에서 `npm install`을 실행하여 `package-lock.json`을 업데이트하고 정합성을 확인했는지 체크 (필수)
- [ ] **결과 보고**: `reports/` 폴더에 리팩토링 전후 비교(성능, 코드 라인 등) 보고서 작성
- [ ] **알림**: 개발 팀에 구조 변경 사항 공유 및 텔레그램 발송
