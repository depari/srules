# 코드 품질 및 안전 가드레일 (Code Quality & Safety Guardrails)

## 1. 구문 무결성 (Syntactic Integrity)
- **금지 사항**: 코드 수정 후 불필요한 중괄호(`}`), 소괄호(`)`), 세미콜론(`;`) 등이 남아서는 안 됩니다.
- **필수 절차**: 
  - 파일 수정 후 반드시 전체 구조를 다시 읽어 구문 오류 유무를 육안으로 확인합니다.
  - 특히 `multi_replace_file_content`나 `replace_file_content` 호출 시 교체 대상과 결과물의 경계가 올바른지 검토합니다.

## 2. 빌드 및 린트 안정성 (Build & Lint Stability)
- **원칙**: 모든 수정 코드는 애플리케이션의 빌드 및 린트 체크를 깨뜨려서는 안 됩니다.
- **금지 사항**: 
  - `any` 타입을 명시적으로 사용하는 것을 지양합니다. (TypeScript의 이점을 유지)
  - `useEffect` 내에서 동기적으로 `setState`를 호출하여 cascading render를 유도하는 코드를 작성하지 않습니다.
- **필수 절차**:
  - 중요한 UI나 로직 수정 후에는 `npm run lint`를 실행하여 린트 오류가 없는지 확인합니다.
  - 빌드 확인(`npm run build`) 시 빌드 작업 종료 전 린트 체크가 포함되어 있는지 확인합니다.
  - **전체 테스트 실행**: 커밋 전 반드시 `npm test`를 실행하여 기존 기능의 회귀(Regression)가 발생하지 않았는지 확인합니다.
  - **E2E 테스트 실행**: 주요 사용자 시나리오(즐겨찾기, 규칙 상세 조회, 검색 등)에 대해 `npx playwright test`를 실행하여 핵심 경로의 무결성을 검증합니다. (로컬에서는 최소한 Chromium 프로젝트 통과 확인 권장)

## 3. TDD 준수 (TDD Adherence)
- **원칙**: 기능 변경이나 개선 시 반드시 테스트 케이스를 먼저 확보합니다.
- **필수 절차**:
  - `tasks/` 폴더에 문제점 개선을 기록할 때는 1) 관련 유닛 테스트 작성, 2) 테스트 실패 확인, 3) 테스트 통과 구현의 순서를 엄격히 따릅니다.

## 4. 의존성 정합성 (Dependency Consistency)
- **원칙**: `package.json` 수정 시 반드시 `package-lock.json`이 동기화되어야 하며, CI 환경에서 `npm ci`가 실패하지 않도록 관리해야 합니다.
- **필수 절차**:
  - 패키지 추가/수정/삭제 시 반드시 `npm install`을 실행하여 `package-lock.json`을 업데이트합니다.
  - 커밋 전 `package.json`과 `package-lock.json`이 함께 포함되었는지 확인합니다.
  - 의존성 관련 수정 시 로컬에서 빌드(`npm run build`)를 수행하여 환경적 문제가 없는지 사전 검증합니다.

## 5. 환경 변수 및 보안
- **금지 사항**: API 키, 토큰 등 민감 정보를 코드에 직접 포함하지 않습니다. `.env.local` 등 설정 파일을 통해서만 사용합니다.
